# Design

## 架构

Vite + React + TypeScript，原生 CSS；生产仅 `dist/` 静态文件。Vite `base: './'`，页面内状态切换，不依赖服务器路由回退。使用原生 `fetch`，不引入服务端代理、数据库或游戏引擎。

界面由页头、场景主视觉、今日支线卡、世界事件区、奖励反馈和 API 设置面板组成。像素品牌、城市、生活场景和奖励素材来自用户提供的 UI 素材包，避免把 API 表单作为首页主角。小屏按单列呈现，装饰不妨碍主要按钮。

## 数据与状态

- `Quest` 包含标题、剧情、描述、步骤、类别、预计分钟、难度、完成条件、奖励与安全替代方案；另保留演示标识。
- 奖励是限定九种属性和合理正整数增量的列表，仅在当前任务完成状态展示。
- 任务状态转换由前端控制，待接受 → 已接受 → 已完成；待接受或已接受可跳过。生成新任务替换当前任务和奖励，避免重复领取。
- 新闻事实对象保留来源标题、URL、名称、摘要及时间；游戏叙事单独存储，AI 不获得覆盖事实证据的权力。
- API 配置、当前任务、热点、请求状态、错误与奖励仅存在组件状态/普通内存。刷新回到默认状态；不保存任务或属性。

## AI Provider

统一任务生成接口屏蔽服务商差异。阿里云默认 `qwen-plus` 和北京地域通用地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`，默认无需填写业务空间 ID；DeepSeek 默认 `deepseek-flash` 和 `https://api.deepseek.com`。Base URL 限定为实现白名单中的所选服务商官方 HTTPS 域名，不支持第三方代理，不允许重定向携带密钥。设置允许用户修改配置，不能假定所有模型支持相同参数。连接测试实际请求所选服务，不以静态配置正确代替成功。

提示词要求安全现实任务和 JSON；响应需要校验字段类型、长度、类别、时长、奖励属性和范围。有限重试后显式报错或进入带演示标识的体验。使用超时/取消控制请求，禁用忙碌操作，避免重复请求与旧响应覆盖新配置。

## 热点适配

阿里云在所配置的同一主机使用原生 DashScope 路径请求启用搜索，检查返回 `output.search_info.search_results` 来源证据，再建立世界事件。本项目未接入 DeepSeek 联网搜索，可基于用户提交的新闻文本创作事件；这不是对服务商能力的否定。只有真实来源证据可以支撑搜索标识；用户提供内容明确标记为未独立核实；演示事件永远保留演示标签。

时间不足以确认时显示未知，不从当前日期臆造发布时间。来源 URL 只允许安全 HTTP(S) 链接，外链设置安全属性。严肃灾难或伤亡内容可只呈现事实，不强行转换任务。

## 安全与验证

密钥直接用于浏览器到服务商的请求，只存内存，不输出完整密钥或原始异常堆栈。自定义地址会接收密钥，因此设置需明确目的地址；跨域、地域、权限问题真实展示，不创建隐藏后端规避限制。

单元测试覆盖 schema、任务状态与 Provider 请求/错误；Playwright 覆盖任务闭环、设置、演示/新闻状态、小屏和刷新清空。构建执行 TypeScript 检查。受控 API 响应只证明前端逻辑；真实凭证、生产 CORS 和远程 Pages 需分别实测后才能声明成功。
